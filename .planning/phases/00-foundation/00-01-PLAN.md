<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (working tree) → git remote | If `.gitignore` is wrong, secrets in `.env` or DB contents in `cache/` leak to remote on first push. |
| `pyproject.toml` declarations → installed environment | A rogue/typo'd dependency name could pull a malicious package (typosquatting). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-01 | Information disclosure | `.gitignore` correctness | mitigate | Explicit literal patterns for `.env`, `cache/`, `output/`, `logs/`, `config.yaml`, `*.sqlite*`. Verified by `git check-ignore`. |
| T-00-02 | Tampering | `pyproject.toml` deps | mitigate | All deps pinned to known PyPI distributions per CLAUDE.md authoritative table. `uv.lock` committed for reproducibility. No `git+` URLs, no `path/` deps. |
| T-00-03 | Information disclosure | `.env.example` | accept | Contains placeholder values only (`sk-ant-REPLACE_ME`, `REPLACE_ME`). No real secrets. |
| T-00-04 | Information disclosure | `config.yaml.example` | mitigate | Contains no secrets — D-14 enforces secrets-only-in-`.env`. config.yaml.example holds runtime knobs only. |
</threat_model>
